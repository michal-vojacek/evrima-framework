# Changelog

Every release states what changed and whether websites need any change. Versioning rules: [docs/framework.md](docs/framework.md).

## 0.1.0 (2026-11-06)

The first release, for testing the deploy (versions 0.x are development releases, docs/framework.md, "Versioning rules"). It contains:

- Package: `evrima` with the version taken from Git tags, exact pins of every dependency, MIT licence.
- Core: application factory, configuration loading with startup checks (`flask evrima check-config`), security headers and a strict CSP, CSRF protection, rate limiter (an IPv6 client counts by its /64), request body limits per view (`BODY_LIMIT` 64 KB, `ADMIN_BODY_LIMIT` 1 MB, `@security.body_limit(bytes)` for views that take files, at most `MAX_CONTENT_LENGTH` 25 MB), `SITE_HOSTS` (required in production; other hosts get a plain-text 400), database session handling, Redis client, health check `/health`, default error pages, `flask evrima version`, minimal example website.
- Database migrations with Alembic (`flask evrima db upgrade | current | revision | remove-module`), one branch each for the framework, the website and every module.
- E-mail over SMTP (`evrima.mail`), with console and memory backends for development and tests.
- Admin languages: Czech and English text catalogues (`translations/*.toml`) with plural forms and a language switch; catalogues of websites and modules are loaded next to the framework's.
- Admin frame: sidebar (a top bar with a menu button below 900 px), user menu, flash messages, dialogs, form helpers, the `/admin/design` cookbook for logged-in administrators (contrast WCAG AA, stacked tables on phones, file upload with previews, gallery and list ordering, busy state of forms, character counter, breadcrumbs, pagination, collapsible sections); jQuery, DataTables and Font Awesome Free vendored.
- Admin login: e-mail and password (at least 12 characters, Argon2id m=19 MiB, t=2, p=1), lockout per e-mail and client after 10 failures, server-side sessions (2 h idle, 24 h at most), password reset and invitations by one-time links, account page (profile, password, log out everywhere), management of administrators, audit log; `flask evrima create-admin | set-admin-email | set-admin-password`.
- Uploads (`evrima.media`): images (JPEG, PNG, WebP) and PDF documents checked by content and decoded only by the decoder of their format, images cleaned of EXIF and saved with WebP and AVIF variants, files served from `/media/`, background upload in the admin with a progress bar and a queue, `evrima.media.take()`. Setting `MEDIA_ROOT`.
- Rich-text editor (`evrima.editor`): headings, paragraphs, bold, links and lists, cleaned with `nh3` on save and on output (`rich` template filter).
- Modules: `create_app(..., modules=[...])` enables the website's modules with their own admin screens, menu items, text catalogue and migration branch; module names are checked, unprotected admin blueprints are refused, generated migrations only touch their own branch's tables and never drop tables without a model; helpers `evrima.admin.forms.parse_id()` / `parse_ids()`. No ready-made content modules: each website writes its own following `docs/modules.md`; the example website's references module is the pattern.
- Honeypot for public forms (`evrima.security.honeypot`): a hidden trap field and a signed render time (3 seconds to 7 days), `{{ honeypot("form") }}` in templates and `honeypot.looks_like_bot(request.form, "form")` in views.
- Telemetry, website side (`evrima.telemetry`): request, error and form events, a cookie-free browser script for page views and clicks (`data-track` labels) with a same-origin beacon, a Redis buffer and `flask evrima telemetry ship` (batches kept in flight until accepted, retried with the same id, one shipper at a time, no redirects). Settings `TELEMETRY_ENDPOINT` and `TELEMETRY_TOKEN`. Level 2 with consent (`TELEMETRY_VISITORS`): a random visitor id in the `evrima_vid` cookie, added to browser events as `vid` only while the visitor allows the named category. Protocol: evrima-telemetry, `docs/protocol.md`.
- Consent banner (`evrima.consent`), the groundwork only: switched on by `CONSENT_CATEGORIES`, the visitor's choice per category in the `evrima_consent` cookie (`CONSENT_VERSION` asks again), a banner and a settings page that work without JavaScript, `consent()` in templates, `evrimaConsent` and the `evrima:consent` event for the website's scripts. Which service needs which category is up to the website.
- Legal pages (`evrima.legal`): skeletons of the privacy policy and the cookies page in Czech and English (`LEGAL_PAGES`), extending the website's layout (`SITE_LAYOUT`); the cookies page lists the framework's own cookies, the website fills in the rest.
- `SITE_LANGUAGE` (`cs` or `en`): the language of the consent banner, the legal skeletons and the fallback error page.
- Static files: fingerprinted URLs (`?v=<hash>`) cached for a year, fonts cached for 30 days as `font/woff2`, everything else revalidated.
- Search engines (`evrima.seo`): `/robots.txt`, `/sitemap.xml`, `/.well-known/security.txt`, `canonical_url()` and the `json_ld` filter, configured by the website (`SITE_URL`, `SITEMAP`, `ROBOTS_BLOCKED_AGENTS`, `SECURITY_CONTACT`, `SECURITY_LANGUAGES`).
- `flask evrima jobs`: periodic jobs for a sidecar container, each in its own app context, stopping on SIGTERM: telemetry shipping every minute; daily `flask evrima media cleanup` and removal of old login records (failed logins after 30 days). Docker files of websites live in the website template (`evrima-framework-app-template`).
- Websites need changes: no (nothing released yet).
